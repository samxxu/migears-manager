# P3-2 — EventBus::emit() docblock claims "The listener list is snapshotted when …

## Finding / 问题

- EN: EventBus::emit() docblock claims "The listener list is snapshotted when the call starts" but the implementation iterates directly over $this->listeners[$event] with no explicit snapshot. PHP's foreach over an array effectively provides this, but the comment implies an explicit mechanism that does not exist.
- 中文: EventBus::emit() 文档注释称「监听器列表在调用开始时被快照」，但实现直接遍历 $this->listeners[$event] 并无显式快照。PHP 的数组 foreach 实际上提供了此行为，但注释暗示了一个不存在的显式快照机制。
- Where / 位置: `src/EventBus.php:118-120 vs :129-131`
- Verification / 验证: static / 仅静态推断

- 2026-10-01 · `owner — migears-manager` · `rejected` — re-checked against the code and probed: the
  documented guarantee is exactly what the bus does, so nothing in that docblock is stale or false.
  - `src/EventBus.php:118-120` states behaviour, not a claim about an array copy the code lacks.
    `foreach ($this->listeners[$event] ?? [] as $listener)` (`src/EventBus.php:129`) iterates the array by
    value, so PHP separates the property array from the one being iterated as soon as a listener writes to
    it: a dispatch in flight sees the list exactly as it was when the call started.
  - Probed outside the repo through this module's own `vendor/autoload.php`, with one listener adding a
    listener and removing another from inside the dispatch: dispatch 1 → `["first","second"]` — the add did
    not run in the dispatch that made it, and the removed listener still ran in that same dispatch;
    dispatch 2 → `["first","second","first","added-during-dispatch"]` — the add is visible from the next
    emit. That is the paragraph's claim, both halves of it, with no explicit snapshot in between.
  - The guarantee is pinned in both directions, so it is not incidental and cannot drift silently:
    `tests/EventBusTest.php:246` (`testListenerRegisteredDuringDispatchRunsOnlyFromTheNextEmit`) and
    `tests/EventBusTest.php:265` (`testListenerRemovedDuringDispatchStillRunsInThatDispatch`).
  - The identical sentence is in the README (`README.md:639`, Chinese mirror `README.md:1599`), so this is a
    deliberate wording shared by code and document rather than documentation drift. No file changed for this
    item. Counter-evidence welcome; if what is wanted is the mechanism spelled out ("foreach iterates the
    array by value"), that is a wording preference and I will make it — but the claim as filed, that the
    comment promises a mechanism the code does not deliver, does not hold.
