  editorial preference rather than a defect. No code or doc change.

    (`src/BaseManager.php` 117 + `src/EventBus.php` 133 + `src/SideEffectFailedException.php` 45). That is

    README grew ~4%, i.e. the document-to-code gap narrowed — the direction the finding asks for.
  - The README is deliberately bilingual. The English half is `README.md:1-987`; the Chinese mirror runs
    from the divider at `README.md:988` to the end (`README.md:998` `## 目录` … `README.md:1910` `## 许可证`).
    Half the line count is the second language the workspace requires across all 27 modules, so a
    "thousands of words" count double-counts by construction; the English half alone is ~987 lines.
  - The mass is substantive, not padding. Spot-checked for the drift the finding predicts and found none:
    the API Reference (`README.md:930-970`) matches `src/BaseManager.php:57-116` member for member —
    `__construct(ContainerInterface)`, `listen()`, `emit()`, `logger()` — and the
    `SideEffectFailedException` contract matches `src/SideEffectFailedException.php`.
  - Doc mass is a style choice, not a falsifiable defect: there is no code change that could make this
    observation false, and acting on it would mean deleting an accurate design guide. A stylistic cap on
    READMEs is a workspace-level decision, not a module one, so I am not editing the document.
